# レンダリング仕様（スライドの完成形）

スライドの完成形は HTML である。`slides.md` は内容の正（タイトル・図の指定・要点）であり、成果物はそれをレンダリングした `slides.html` とする。テキストベースで止めない。

## 成果物
- `works/<案件>/slides.md`：内容仕様（従来どおり）
- `works/<案件>/slides.html`：完成スライド。単一ファイルで完結させる（CSS・JS・SVG はすべて埋め込み、外部依存なし。オフラインで開けること）

## テンプレートの解決順
レンダリング時は次の順でテンプレートを探し、最初に見つかったものを使う。使ったテンプレートを lint-report に記録する。
1. 案件固有：`works/<案件>/template/`（その案件専用の指定がある場合）
2. リポジトリ共有：`templates/` 直下に案件が指定するもの
3. 標準：`templates/standard/`（デジタル庁デザインシステム DADS のトークンに基づく標準テンプレート）

テンプレートは「型」と直交する層である（形式制約・設計原則と同じ）。テンプレートの差し替えで内容（タイトル・図・要点）は変えない。

## 標準テンプレート（DADS 準拠）
- キーカラー：Blue-900 `#0017C1`。淡色背景：Blue-50 `#E8F1FE`、Blue-100 `#D9E6FF`。本文 `#333333`、罫線グレー `#949494`、フォーカス `#FFD43D`
- 書体：Noto Sans JP（システムフォントへのフォールバック付き）。行間 170% を本文の基準にする
- スライド寸法：16:9（1280×720 を基準単位とし、表示はビューポートにフィット）
- 操作：矢印キー／クリックで前後移動、スライド番号と進捗表示、印刷時は全スライド縦並び（@media print）
- アクセシビリティ：テキストと背景のコントラスト比 4.5:1 以上を保つ。色だけで意味を伝えない（ラベルや形を併用する）

## 図解の作法（u1氏の図解投稿を参考にした原則）
図の描き方は、X で技術解説の図解を継続的に発表している u1（Yuichi Uemura）氏の作法を参考にする。
- 図は1枚で完結させる。図の上部に、その図で言いたいこと（結論）を置く
- 要素は箱と矢印に絞り、装飾的な要素を排する。形の種類を増やさない
- 色は意味で使い分け、色数を絞る（カテゴリが色に対応する。注目させたい箇所だけ色を強くする）
- グルーピングは枠線よりも余白と整列で表現する
- 注釈は図の外の脚注ではなく、関係する要素の近くに短く置く
- 読み手の目線の流れ（左から右、上から下）に逆らわない

## 図解の実装ルール
- 図は outline が指定した形を、インライン SVG または HTML/CSS の構造図として実際に描く。図のプレースホルダや「図：〜」という文章で済ませない
- 図の中のテキストはスライド本文と矛盾させない。数値・固有名は slides.md の記述と一致させる
- 図の部品にはラベルを付け、色分けには凡例か直接ラベルを併用する（色のみで区別しない）
- 1スライドの情報量：図が主、文章は要点1行＋補足まで。図の中に長文を詰め込まない

## 視覚 lint（フェーズ2の lint に追加する層）
- [ ] outline の図指定どおりの形で実際に描かれているか（全枚同型への退化がないか）
- [ ] 図内テキストと本文・数値が一致しているか
- [ ] テンプレートの解決順に従い、使用テンプレートが記録されているか
- [ ] コントラストと文字サイズが標準テンプレートの基準を満たすか（テンプレート側の担保＋個別の逸脱チェック）
- [ ] 単一ファイルで完結し、外部リソース参照がないか
