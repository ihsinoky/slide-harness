# anti-slop リント チェックリスト

生成とは別パスで実行する。各項目はパス／不合格で判定し、不合格は理由を1行で記録する。

本ファイルは lint の共通層（全型共通）。これに加えて、主型・副型それぞれの型リード（`core/type-leads/`）の「型固有 lint」を重ね、3層で判定する（プロセスは `core/process.md` フェーズ2）。判定は層ごとに別パスで読み直さず、スライドを1回読む単一パスでまとめて行い、層別の節を持つ1つのレポートに記録する。

## タイトル

- [ ] タイトルが主張文になっているか（名詞題・体言止めの題目だけになっていないか）
- [ ] タイトルが `storyline.md` の自スライドの主張と一致し、主張が1つに絞られているか（2つの主張を1枚に詰めていたら不合格）
- [ ] 曖昧な一語に意味を詰め込んでいないか（例：「差」「活用」「推進」「最適化」だけで内容を代表させていないか）
- [ ] タイトルだけ読んで、読み手が文脈を補完しなくても意味が取れるか（認知負荷テスト）

## メッセージと読み手モデル

- [ ] 図だけを見て、タイトルの主張を言い直せるか（図が部品・層・用語の列挙になっていたら不合格。列挙は「何が含まれるか」であって主張ではない）
- [ ] 仕組みや要素を紹介するスライドでは、各要素が読み手にとって何を良くするか（何が落ちるか、何ができるようになるか）が読み取れるか（名前と役割の対応だけでは不合格）
- [ ] 要素の並びが読み手の出発点から始まっているか（読み手が体験する問題、既に知っている図や概念 → 原因や仕組み → 対策の順。作り手の分類や内部構造の順に並べない）
- [ ] 前に出た図やモデルを前提にするスライドは、その図と同じ配置を再掲し、差分にだけ印をつけているか（対になるスライドは1組として設計し、配置をそろえる）
- [ ] 読み手の語彙にない内部用語・略号が、説明なしに出ていないか（作り手側の呼び名は読み手の言葉に置き換える）

## 内容

- [ ] 主張に数値または出典があるか（「大幅に」「多くの」などの無根拠な程度表現で済ませていないか）
- [ ] 言いたいことの優先順位（優先順位マップ）とスライドの扱いが一致しているか（低優先の内容が大きく扱われていないか）
- [ ] 情報を全部同じ重さで並べていないか（要点と補足の階層があるか）

## 図とレイアウト

- [ ] 文章を隠しても、図だけでそのスライドのメッセージが伝わるか
- [ ] 図の形が、比べ方（分類）と一致しているか
- [ ] 全スライドが同じレイアウトの繰り返しになっていないか（テンプレ slop）。同じ形が続く場合は、内容上の理由があるか
- [ ] 図の中に文を詰め込んでいないか（図の中の文字は部品名・値・短い注記まで）

## 文章

- [ ] 日本語の推敲（主述のねじれ、非生物主語、形式の偏重）を通したか
- [ ] 装飾（太字・箇条書きの濫用）で情報密度を落としていないか

## 全体

- [ ] 読み手が再構成した主張の列が、`storyline.md` のストーリーラインと一致するか（コールドリード。タイトルと図を通読して受け取った物語が、設計した線と一致するか）
- [ ] 数値がすべて出典と一致するか

## 指摘ナレッジとの関係

使う人の指摘のパターンは `core/review-feedback.md` に蓄積する。フェーズ2・3では、本チェックリストとあわせて同ファイルの全パターンを先回りで確認する。
