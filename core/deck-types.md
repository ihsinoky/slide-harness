# スライド資料の型類型（7型）

根拠：型類型調査（2026-11-15）。Speaker Deck 年間最多閲覧（2024／2025 各30件）とドクセルの人気スライドを主題ではなく機能で帰納分類し、アリストテレスの弁論3種から IMRaD、ポストモーテム様式までの理論と突き合わせて統合した。調査レポートは `~/workspace/research_notes/slide-deck-type-taxonomy-20261115-0702/report.md`。

## 分ける軸

- **主軸：読み終えた後に、読み手が行う仕事**。判定テストは1つだけ：「この資料が成功したとき、読み手は具体的に何をした／何を持ち帰った状態になるか」
- 副軸（診断の補助にだけ使う）：時間の向き（未来／現在／過去／なし）、証拠の性質（予測／実績・同一性／定点観測／実測／因果／定義と例／事例と物語）
- 類型に入れないもの：形式制約（PechaKucha、10/20/30）、1枚の設計原則（Assertion-Evidence、チャート選択）、美学（Presentation Zen）、主張の内部構造（ピラミッド原則、空・雨・傘）。これらは型と直交する層であり、型の下で使う

## 運用

- 資料ごとに **主型1つ＋副型0〜1つ** を類型診断（フェーズ0）で定める。実在の資料は混合型が多いが、成功条件を決めるのは主型である
- 型は拡張（`extensions/`、`core/extensions.md` の仕組み）で core を書き換えずに追加できる。拡張の型も本ファイルの型と同じく「読み手の仕事」で定義し、主軸テストで既存型と重ならないことを条件とする
- 各型のロール定義（ミッション／観点／スコア基準／典型構成と疑問チェーン／型固有 lint）は `core/type-leads/` に置く。本ファイルは類型の定義そのもの

## 7型

### ① 決断提案型（Recommendation）
- 読み手の仕事：決断者（上司・会議体・顧客）が、施策の採否と資源配分を決める
- 典型構成：結論（勧告）→ 状況・複雑化・問い（SCQ）→ 根拠（代替案比較）→ 実行計画・コスト・リスク → 決めてほしい事項
- 内容基準：代替案との比較、反対論への回答、コストと不確実性の明示、事実と解釈の分離
- 特有の失敗：不利な代替案・前提の隠蔽、効果予測を実績のように書く誇張、都合のよい事例だけの cherry-picking

### ② ピッチ／招請型（Pitch & Invitation）
- 読み手の仕事：資源提供者・参加候補者（投資家・求職者・有権者・顧客）が、その対象に資源を出すか／加わるかを判断する。持ち帰りは対象への信頼と参加意欲
- 典型構成：対象の目的・ビジョン → 解く課題 → 提供物・事業 → 実績／トラクション → 市場・機会 → 人・文化 → 条件と依頼（ask／応募方法）
- 内容基準：対象の実態の具体性（数字・人・顧客の声）、「なぜ今・なぜこの主体か」、不利な情報も含む現実的な開示
- 特有の失敗：市場規模・成長率の水増し、実績と予測の混同、参加後に効く情報（離職率・解約率など）の欠落

### ③ 状況把握型（Status / Monitoring）
- 読み手の仕事：継続的な関係者が、計画との差分を掴み、介入するか・エスカレーションするかを判断する
- 典型構成：全体判定（RAG 等）→ 計画対比（進捗・予算・日程の差分）→ 当期の変化 → リスク・阻害要因 → 次期予定 → 判断・支援を求める事項。前回と同じ物差しで反復する
- 内容基準：基準線（計画・前回・目標）との差分が全情報の中心。変化のない項目は書かないか短く。悪いニュースは早期に、同格に
- 特有の失敗：watermelon reporting（外は緑・中は赤）、進捗率の水増し、活動量の一覧で差分を代替する、毎回形式が変わり比較不能

### ④ 成果・検証報告型（Results / Accountability）
- 読み手の仕事：評価者が、事前に約束／仮説したことに対して何がどこまで成ったかを判定し、次の資源配分や採否の材料にする
- 典型構成：目的・事前の目標／仮説 → 方法（やり方・条件）→ 結果（実測、解釈を混ぜない）→ 考察（意味・限界・既存知見との関係）→ 結論と次への示唆（IMRaD 型）
- 内容基準：方法の透明性（再現可能性）、結果と解釈の分離、未達・否定的結果の同格の報告、測定条件の明示
- 特有の失敗：成功指標だけを選ぶ粉飾、指標の事後的すり替え、未達の埋没、方法を書かず再検証不能にする、活動報告で成果報告のふりをする（③との混同）

### ⑤ 原因究明・学習型（Postmortem / Case Retrospective）
- 読み手の仕事：同業者・将来の自分たちが、因果モデルと教訓を持ち帰り、何を変えるか（再発防止・やり方の更新）を決める
- 典型構成：要約と影響 → 時系列（タイムライン）→ 寄与要因／根本原因（複数）→ うまくいったこと／いかなかったこと／幸運だったこと → 教訓 → 改善アクション（担当・期限付き）
- 内容基準：時系列の正確さ、事実と推測の区別、個人ではなくシステム・プロセスへの帰属（blameless）、教訓が具体的アクションに落ちること
- 特有の失敗：責任追及への変質、因果に触れない反省文、単一原因への決めつけ、「気をつける」など検証不能な教訓

### ⑥ 説明・教育型（Explanation / Teaching）
- 読み手の仕事：学習者が、使える概念モデル・手順を持ち帰る（判断は下さない。「自分でできる／判断できる」状態になる）
- 典型構成：全体地図・目次 → 前提知識 → 概念（定義 → 例 → 反例）→ 手順／使い方 → 演習・ゴール確認 → まとめと次に学ぶこと
- 内容基準：学習者の前提に合わせた順序（易→難、前提→応用）、1概念ずつの足場、例と演習の存在、網羅性より理解可能性
- 特有の失敗：前提を飛ばす専門家の呑み込みすぎ、網羅のための密度過多、発表者の知識目録化、正確さを犠牲にする単純化の放置

### ⑦ 視点提示・ビジョン型（Framing / Vision）
- 読み手の仕事：採否は求めない。読み手の見方・判断基準・共有された価値が変わる
- 典型構成：問題提起・違和感 → 現状の見方（What Is）→ 新しい見方／ありうる姿（What Could Be）の対比 → 事例・物語による裏付け → 判断基準・原則の言語化 →（任意の）招請
- 内容基準：フレームの新しさと一貫性、語り手の経験・信頼（ethos）、抽象論を支える具体的な事例・物語、価値のトレードオフ（何を捨てるか）の明示
- 特有の失敗：検証も事例もない標語の連呼、フレームに合う事例だけの選別、情緒に寄せて事実確認を免除させる
