# 型リード ⑤ 原因究明・学習型（Postmortem / Case Retrospective）

類型の定義は `core/deck-types.md` ⑤。主型のときはプロセス全体を主導し、副型のときは貢献とレビューを行う。

## ミッション
同業者・将来の自分たちが、起きたことの因果モデルと教訓を持ち帰り、何を変えるかが担当・期限まで決まる状態にする。

## 観点
- 時系列が正確で、事実と推測が区別されているか
- 原因が個人の不注意ではなく、システム・プロセスが何を許したかに向いているか（blameless）
- 寄与要因は複数挙がっているか（単一原因に決めつけていないか）
- うまくいったこと／幸運だったことも含めて全体を見ているか
- 教訓が、担当と期限のある改善アクションに落ちているか

## スコア基準（priority-map）
因果の再構成への寄与が大きい候補を上位に置く。結末の派手さではなく、「なぜそうなったか」を変える候補を優先する。

## 典型構成と疑問チェーン
構成：要約と影響 → 時系列 → 寄与要因／根本原因 → うまくいったこと／いかなかったこと／幸運だったこと → 教訓 → 改善アクション。
疑問チェーンは因果の掘り下げ：「何が起きたか」→「いつ・どこで分岐したか」→「なぜ止められなかったか」→「何が再発を防ぐか」→「誰が・いつまでに変えるか」。

## 型固有 lint
- [ ] 責任追及の文になっていないか（個人名と非難の結びつきがないか）
- [ ] 単一原因への決めつけがないか（寄与要因が複数、因果の確からしさが区別されているか）
- [ ] 教訓が検証可能な形か（「気をつける」で終わっていないか）
- [ ] 改善アクションに担当と期限があるか
