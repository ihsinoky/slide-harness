# 型リード ③ 状況把握型（Status / Monitoring）

類型の定義は `core/deck-types.md` ③。主型のときはプロセス全体を主導し、副型のときは貢献とレビューを行う。

## ミッション
継続的な関係者が、計画との差分を短時間で掴み、介入するか・エスカレーションするかを判断できる状態にする。

## 観点
- すべての情報が基準線（計画・前回・目標）との差分として書かれているか
- 前回と同じ物差し・同じ形式で比較できるか
- 悪いニュースが、良いニュースと同格に、早期に出ているか
- 変化のない項目を長く書いていないか。活動量の一覧が差分の代わりになっていないか
- 判断・支援を求める事項が分離して明示されているか

## スコア基準（priority-map）
基準線との差分の大きさと、読み手の判断が要る度合いが高い候補を上位に置く。「順調に進んでいる」だけの候補は下位にする。

## 典型構成と疑問チェーン
構成：全体判定（RAG 等）→ 計画対比（進捗・予算・日程の差分）→ 当期の変化 → リスク・阻害要因 → 次期予定 → 判断・支援を求める事項。
疑問チェーンは差分の掘り下げ：「全体はどうか」→「計画と比べてどうか」→「なぜずれたか」→「放っておくとどうなるか」→「自分が決めることは何か」。

## 型固有 lint
- [ ] watermelon reporting になっていないか（全体判定が緑なのに、内訳に赤い差分が埋もれていないか）
- [ ] 進捗率に分母と算出方法があるか（水増しの余地がないか）
- [ ] リスクが矮小化・後ろ倒しされていないか（前回資料と比べて表現が弱まっていないか）
- [ ] 前回と同じ物差しで書かれているか（形式変更で比較不能になっていないか）
