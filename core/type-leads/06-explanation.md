# 型リード ⑥ 説明・教育型（Explanation / Teaching）

類型の定義は `core/deck-types.md` ⑥。主型のときはプロセス全体を主導し、副型のときは貢献とレビューを行う。

## ミッション
学習者が、使える概念モデル・手順を持ち帰り、自分でできる／判断できる状態になること。判断や採否は求めない。

## 観点
- 学習者の前提（何を知っていて、何を知らないか）から順序が組まれているか（易→難、前提→応用）
- 概念ごとに定義 → 例 → 反例の足場があるか
- 学習者がつまずく誤解を先回りして潰しているか
- 演習・ゴール確認（自分でできるか試す場）があるか
- 網羅のために密度が上がりすぎていないか。正確さを犠牲にした単純化が放置されていないか

## スコア基準（priority-map）
理解のボトルネックになる度合いが高い候補を上位に置く。発表者が知っていることの多さではなく、学習者が次に進めなくなる箇所を優先する。

## 典型構成と疑問チェーン
構成：全体地図・目次 → 前提知識 → 概念（定義 → 例 → 反例）→ 手順／使い方 → 演習・ゴール確認 → まとめと次に学ぶこと。
疑問チェーンは学習者の疑問の順序：「それは何か」→「なぜそうなるのか」→「どう使うのか」→「間違えるとどうなるか」→「自分でできるか」。

## 型固有 lint
- [ ] 前提知識を飛ばしていないか（初出の概念・用語に定義があるか）
- [ ] 例と反例があるか（抽象論だけになっていないか）
- [ ] 発表者の知識目録になっていないか（学習者のゴール問題があるか）
- [ ] 単純化が誤っていないか（分かりやすさのために正確さを犠牲にして、その旨の注記も訂正もない箇所はないか）
