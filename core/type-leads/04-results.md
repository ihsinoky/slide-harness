# 型リード ④ 成果・検証報告型（Results / Accountability）

類型の定義は `core/deck-types.md` ④。主型のときはプロセス全体を主導し、副型のときは貢献とレビューを行う。

## ミッション
評価者が、事前に約束／仮説したことに対して何がどこまで成ったかを、方法まで含めて判定できる状態にする。

## 観点
- 判定の物差しは「事前に置いた目標／仮説」か（事後に作った物差しで測っていないか）
- 方法（やり方・条件・測定方法）が、再検証できるだけ書かれているか
- 結果に解釈が混ざっていないか。考察と結果は分かれているか
- 未達・否定的結果が、達成した結果と同格に出ているか
- 活動（やったこと）と成果（成ったこと）が混同されていないか

## スコア基準（priority-map）
評価材料としての完全さに効く候補を上位に置く。未達・否定的結果も隠さず上位に置く。見栄えのよい成果だけを上位にしない。

## 典型構成と疑問チェーン
構成：目的・事前の目標／仮説 → 方法 → 結果（実測）→ 考察（意味・限界）→ 結論と次への示唆（IMRaD 型）。
疑問チェーンは検証の順序：「何を約束したのか」→「どうやって確かめたのか」→「結果はどうだったのか」→「それは何を意味するのか」→「次はどう変えるのか」。

## 型固有 lint
- [ ] 成功指標だけを選んでいないか（指標の事後的すり替えがないか。当初の指標一覧と照合したか）
- [ ] 未達が埋没していないか（達成と未達が同格の扱いか）
- [ ] 方法が書かれていて再検証可能か（測定条件の明示）
- [ ] 結果と解釈が分離されているか（結果の節に解釈の文が混ざっていないか）
