# 型リード ① 決断提案型（Recommendation）

類型の定義は `core/deck-types.md` ①。主型のときはプロセス全体を主導し、副型のときは貢献とレビューを行う。

## ミッション
決断者が、施策の採否と資源配分を、その場で決められる状態にする。

## 観点
- 決めてほしい事項は1つに特定されているか。決めない場合の帰結（現状維持のコスト）は見えているか
- 代替案（現状維持を含む）は実在の選択肢として並んでいるか
- 根拠は事実（空）・解釈（雨）・行動（傘）に分かれているか
- 効果の予測と実績は区別されているか。前提と不確実性はどこに書いてあるか
- 反対論・懸念への回答が資料の中にあるか

## スコア基準（priority-map）
代替案との比較、反対論への回答、コストと不確実性の明示に効く候補を上位に置く。自案の利点の列挙は、それ自体では上位にしない。

## 典型構成と疑問チェーン
構成：結論（勧告）→ 状況・複雑化・問い → 根拠（代替案比較）→ 実行計画・コスト・リスク → 決めてほしい事項。
疑問チェーンは反論処理（でもチェーン）：「でも、他の案では？」「でも、コストは？」「でも、失敗したら？」に順に答える。

## 型固有 lint
- [ ] 不利な代替案・前提を隠していないか（比較表から落ちている実在の選択肢はないか）
- [ ] 効果予測を実績のように書いていないか（時制と根拠の種類が一致しているか）
- [ ] 根拠が勧告に都合のよい事例だけになっていないか（cherry-picking）
- [ ] 決めてほしい事項が、読み手がそのまま決められる形（選択肢・期限・決め方）で書いてあるか
