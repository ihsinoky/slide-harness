# 拡張型：記録・参照型（Archive / Record）

拡張 `record-archive` が提供する型。core の7型にはない「後から辿るための記録」という読み手の仕事を担う。status は sample（未検証）。

## 定義
- 読み手の仕事：将来の読み手（半年後の自分、引き継ぎ先、監査する人）が、その場にいなくても「何が決まり、何を根拠に、誰が決め、何が未決か」を正確に再構成できる
- 典型構成：概要（対象・期間・結論の一覧）→ 経緯（時系列）→ 決定事項（根拠と決定者つき）→ 未決・持ち越し → 関連資料への参照
- 内容基準：事実と解釈の分離、決定と未決の区別、時点の明記（いつの情報か）、参照先の実在
- 特有の失敗：結論だけ残して根拠が消える、未決事項が「決まったこと」の顔をして混ざる、時点が書かれず古い情報と新しい情報が混線する

## ミッション
読み手が後から来ても迷子にならないこと。説得も判断の促しもしない。正確さと辿りやすさが成功条件であり、面白さは条件ではない。

## 観点
- 決定事項に「根拠」と「決定者」と「日付」が揃っているか
- 未決・持ち越しが、決定と明確に区別して置かれているか
- 時系列が追えるか（いつの出来事か、いつの情報か）
- 事実と解釈・推測が混ざっていないか（推測には推測と書く）
- 参照先（議事録、PR、チケット等）が実在し、辿れるか
- その場の全員が知っている前提（暗黙の文脈）に依存していないか

## スコア基準
「後から困る度合い」で順位をつける。根拠を失うと再構成できなくなる項目（決定の理由、却下した代替案とその理由、未決の期限）を上位に置く。経緯の面白さでは順位をつけない。

## 典型構成と疑問チェーン
構成：概要 → 経緯 → 決定と根拠 → 未決・持ち越し → 参照。
疑問チェーンは将来の読み手の疑問の順序：「何の記録か」→「何が決まったか」→「なぜそう決めたか」→「何がまだ決まっていないか」→「詳しくはどこを見ればいいか」。

## 型固有 lint
- [ ] 決定事項に根拠・決定者・日付があるか
- [ ] 未決事項が決定と混ざっていないか
- [ ] 時点の書かれていない情報がないか
- [ ] 推測に推測と明記されているか
- [ ] 参照先が実在するか（リンク・番号の照合）
