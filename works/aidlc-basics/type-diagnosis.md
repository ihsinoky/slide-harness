# 類型推定（フェーズ0）

## 指定と推定
- 主型：⑥ 説明・教育型（ユーザーが型を指定して開始、2026-11-16）。読み手の仕事は「AI-DLC の全体像のメンタルモデルを持ち帰り、次に自分で学べる／触れる状態になること」であり、判断や採否は求めない。⑥の定義と一致する。
- 副型：なし（候補を置かない）
  - 根拠：全体像の地図づくり自体が⑥の仕事であり、別の型の成功条件を持ち込むと密度が上がって地図が濁る。⑥の lint に「網羅のために密度が上がりすぎていないか」がある。試走として「副型なし」の運用も未検証だったため、その検証も兼ねる。
- 対抗仮説：同じ⑥でも「具体例のウォークスルー中心」で組む案（1つの Intent が流れる様子を追うことで学ぶ）。priority-map の差分として G0 で提示する。

## プロセス計画
- 力点：フェーズ0（学習者の前提の特定）とフェーズ1（地図を先に置く構成）
- 疑問チェーン（⑥）：それは何か → なぜそうなっているのか → どう使うのか → 間違えるとどうなるか → 自分でできるか
- 有効化する型固有 lint：⑥（前提知識の飛ばし、例と反例、知識目録化、単純化の誤り）
- 前提（仮置き、G0 で確認）：学習者はソフトウェア開発の基本的な流れ（要求→設計→実装→テスト→運用）は知っているが、AI-DLC は未経験。AI コーディングツールは触ったことがある程度
- 前提の拡張（2026-11-16、G0 提示後にユーザー指定）：説明は医療機器規制拡張（AWS サンプル）を適用した構成を前提とし、プラグインの仕組みを含む。拡張の事実関係は同リポジトリ README で確認済み（拡張＝規格ごとのルールファイル＋テンプレート、コア変更はステージ終了前の拡張成果物生成の必須節、規格は Requirements Analysis で opt-in、成果物は aidlc-docs/regulatory/ に並走生成）
