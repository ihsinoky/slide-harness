# verification（フェーズ3）

## コールドリード
- 地図（1枚目）→ 部品の拡大（2〜9枚目）→ 具体例（10枚目）→ 確認（11枚目）の順で、初学者が「今どの部品の話か」を見失わない
- 3枚目の V字対応が早い段階にあるため、医療機器側の学習者は既存知識に接続してから新しい概念（Intent、適応型、拡張）に入れる

## 事実の照合（⑥の力点＝単純化しても誤っていないか）
- 拡張の仕組み：規格ごとのルールファイル＋テンプレートをルール置き場へ差し込む／コア変更は「ステージを閉じる前に拡張成果物を生成する」必須節の追加が中心／opt-in は Requirements Analysis（Inception 内）／成果物は aidlc-docs/regulatory/ に並走生成／対象9規格（IEC 62304、ISO 14971、FDA 設計管理・サイバーセキュリティ、IEC 62366-1、ISO 13485、IEC 82304-1、EU MDR、HIPAA）— 拡張リポジトリ README と一致
- 規制成果物の例：リスク分析（FMEA）、トレーサビリティマトリクス、設計履歴ファイル（リリース時）— README の生成物構造と一致
- AI-DLC 本体：3フェーズ、Intent 起点、承認ゲート、成果物の蓄積（状態ファイルと監査ログ）、適応型のステージ選択、Unit of Work／Bolt、Mob Elaboration／Construction — AI-DLC の公開構成と一致
- 会社固有の情報は含んでいない（ウォークスルーは一般的な変更例）
