# スライド1
分類: 全体像
タイトル: slide-harness は、AI のスライド生成を、構造化された・検証可能な資料づくりのワークフローに変える基盤である
図の文字: slide-harness ＝ 資料づくり全体の進め方 / ふつうのAI生成はここだけ / 意図を合わせる / 読み手と成功条件（承認 G0） / 構成を決める / 型と目次（承認 G1） / AIが生成する / スライドを描く / 検査して直す / lint と検証（承認 G3） / AIが作るのは3番目だけ。前後は人との合意と検査の工程です / 支える仕組み / 型：資料ごとの物差し / 拡張：型・ロール・デザインを足す / 規約：図解ガイドなど作り方の決まり
要点: 意図の取り込みから構成・生成・検査までをフェーズで案内し、すべての決定点では人間が承認します。繰り返せて、経緯を追える進め方です
注記: 骨格と自己説明の言い回しは、AI-DLC（awslabs/aidlc-workflows、MIT-0）へのオマージュとして借りています

# スライド2
分類: プロセス
タイトル: 進み方は4フェーズと3つの承認ゲートで、各フェーズに成果物が残る
図の文字: フェーズ0 意図 / intent / priority-map / フェーズ1 構成 / outline / フェーズ2 生成 / slides.md / slides.html / フェーズ3 検証 / verification / G0 / G1 / G3 / 承認は G0（意図と型）・G1（タイトル目次）・G3（最終）の3回 / 各フェーズの成果物が案件フォルダに残り、後から経緯をたどれる
要点: 承認は意図・目次・最終の3回だけ。途中経過はすべてファイルに残ります

# スライド3
分類: なぜプロセスか
タイトル: AI スライドのよくある失敗は、意図合わせ・検査・直し方の工程がないことから起きる
図の文字: よくある問題 / なぜ起きるか / プロセス側の対策 / 頼んだつもりと違う資料が出てくる / 意図合わせの工程がない / フェーズ0の聞き取りと G0 / もっともらしいが、中身のないスライドばかり / 検査が作った側の自己採点 / 生成と lint を別パスに分離 / 一部を直したいだけなのに、全部作り直しになる / 直し方の決まりがない / 変更の種類ごとに戻るゲート
要点: 問題・原因・対策は1対1で対応します。原因はモデルの性能ではなく、工程の欠落です

# スライド4
分類: 型
タイトル: 資料の型は「読み手の仕事」で決まる7つがあり、主型1つ＋副型最大1つで診断する
図の文字: ① 決断提案 / ② ピッチ／招請 / ③ 状況把握 / ④ 成果・検証報告 / ⑤ 原因究明・学習 / ⑥ 説明・教育 / ⑦ 視点提示・ビジョン / 主型1つ＋副型最大1つ。この資料は主型⑥（説明・教育）、副型②（ピッチ／招請）
要点: 型は見た目ではなく、読み終えた後に読み手が行う仕事で決まります

# スライド5
分類: 標準の仕組み
タイトル: 標準の仕組みは core の部品でできていて、案件ごとに作るのは内容だけだ
図の文字: core（正はここに1つ） / 型と型リード ×7 / 型ごとの物差し（観点／スコア基準／構成／型固有 lint） / ロール / ファシリテータ／主型リード／副型リード（最大1つ） / プロセスと規約 / 4フェーズと承認ゲート／図解規約（全層を横断し、不変） / テンプレート / 標準デザイン（IBM Carbon）＝表現の層 / 実行環境（バインディング） / GitHub Copilot（現行の正） / M365 Copilot Studio（同じ core を移植） / 案件フォルダ（works/＜案件＞） / 案件ごとに作るのは内容だけ / 成果物と記録がここに残る
要点: 型リードが型ごとの物差しを持つため、同じプロセスでも型が決まれば候補の並び・構成・検査がまとめて切り替わります

# スライド6
分類: 拡張
タイトル: 型・ロール・デザインは core を書き換えずに拡張として足し替えられる
図の文字: core（正はここに1つ） / 型と型リード ×7 / 型ごとの物差し（観点／スコア基準／構成／型固有 lint） / ＋ 型を足せる / ロール / ファシリテータ／主型リード／副型リード（最大1つ） / ＋ ロールを足せる / プロセスと規約 / 4フェーズと承認ゲート／図解規約（全層を横断し、不変） / 変えられない / テンプレート / 標準デザイン（IBM Carbon）＝表現の層 / ＋ デザインを足せる / 拡張の見本（型） / extensions/record-archive / 記録・参照型（status: sample） / 拡張の見本（デザイン） / extensions/design-note（sample） / パワポ／HTML から色と書体を取り込み
要点: 変えられるのは印のついた3か所だけ。合成は加算のみで、名前が衝突したら止まります
注記: 拡張を外せば素の core に戻ります。検証を通った拡張だけがフェーズ0の候補に入り、使った拡張は診断記録に残ります
