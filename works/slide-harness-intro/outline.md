## タイトルだけの目次（コールドリード用）

1. AIスライドができなかった原因は、生成能力ではなく、意図がずれたまま圧縮が始まることにある
2. slide-harnessは、優先順位マップを承認されるまで、要約も成形も始めない
3. タイトルだけ読んで話が通らなければ、そのスライドはまだ作る段階にない
4. 間違いは目次の段階で見つければ、直すのはその1行で済む
5. 作ったAIにそのまま採点させないので、「大幅に改善」のような根拠のない一文が残らない
6. あなたが決めるのは最初と目次と最後の3回だけで、間の作業は全部プロセスが引き受ける

## でもチェーン（必然性の鎖）

1 → 2：原因が「圧縮の開始位置」なら、直す手は圧縮を始める位置をずらすことになる
2 → 3：「でも、意図が合っても構成が間違っていたら？」
3 → 4：「でも、間違いが見つかっても、直すのが大仕事なら意味がないのでは？」
4 → 5：「でも、構成が良くても、本文そのものが slop だったら？」
5 → 6：「でも、それ全部やるのは重そう」
6：結び。あなたのアクションが見える形で閉じる

## スライドごとの内訳

### 1. AIスライドができなかった原因は、生成能力ではなく、意図がずれたまま圧縮が始まることにある
- 前のスライドから生まれる疑問：—（導入。読み手の「AIにはできない」という結論から受ける）
- 対応する優先順位：A1（10）、A2（10）
- 図の形：因果（数が無い論点）— 頼む → その場で要約・圧縮 → 優先順位がずれたまま成形 → 直しようがない、という原因の連鎖
- 要点1行の候補：失敗体験は本物で、付け替えるのは原因の帰属だけ

### 2. slide-harnessは、優先順位マップを承認されるまで、要約も成形も始めない
- 前のスライドから生まれる疑問：「原因が圧縮の開始位置なら、どう直すのか」
- 対応する優先順位：B1（10）
- 図の形：手順と時間 — フェーズ0（素材を全部出す拡散 → スコア付け → G0承認）を手順で描き、G0の位置で「ここまでは圧縮ゼロ」を線で区切る
- 要点1行の候補：手綱は生成の上手さではなく、圧縮を始める位置にある

### 3. タイトルだけ読んで話が通らなければ、そのスライドはまだ作る段階にない
- 前のスライドから生まれる疑問：「でも、意図が合っても構成が間違っていたら？」
- 対応する優先順位：B5（8）
- 図の形：前と後（対比）— 名詞題「プロセスの概要」と主張文タイトルを並べ、タイトルだけを順に読むコールドリードで話が通るかを試す場面を描く
- 要点1行の候補：構成の良し悪しは、本文を作る前にタイトルだけで試せる

### 4. 間違いは目次の段階で見つければ、直すのはその1行で済む
- 前のスライドから生まれる疑問：「でも、間違いが見つかっても、直すのが大仕事なら意味がないのでは？」
- 対応する優先順位：A4（9）、B3（9）、C2（6・全体地図はここに畳む）
- 図の形：手順と時間 — フェーズ0–3とゲート G0/G1/G2/G3 を横軸に並べ、差し戻しコストが段階ごとに上がることを示す。目次（G1）が最も安い戻し点
- 要点1行の候補：早く見つけることに価値があるのは、直すのが一番安い段階だから

### 5. 作ったAIにそのまま採点させないので、「大幅に改善」のような根拠のない一文が残らない
- 前のスライドから生まれる疑問：「でも、構成が良くても、本文そのものが slop だったら？」
- 対応する優先順位：A3（9）、B2（9）
- 図の形：役割分担 — 生成パスと lint パスを2レーンに分け、lint 側にチェック項目（主張文か／数値に出典があるか／優先順位と扱いの一致）を置く。不合格は該当スライドだけ差し戻す
- 要点1行の候補：本文の質は、生成の上手さではなく別の検査で担保する

### 6. あなたが決めるのは最初と目次と最後の3回だけで、間の作業は全部プロセスが引き受ける
- 前のスライドから生まれる疑問：「でも、それ全部やるのは重そう」
- 対応する優先順位：B4（8）、B7（6）、C1（6・試走の実演はここで触れる）
- 図の形：役割分担 — 全体地図の上に人間の判断3点（G0優先順位／G1目次／G3最終）だけを印し、拡散・構成・生成・lint・照合はプロセス側に置く
- 要点1行の候補：全部をチェックし直すのではなく、効く3点だけを握る。この資料もその3点だけで作られた

- outline の並びはプロセスのフェーズ順ではなく、読み手の疑問の鎖（でもチェーン）で決める。フェーズ順に並べると機能紹介になり、必然性が消える
